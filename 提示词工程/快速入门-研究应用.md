# 提示词工程：面向研究的快速入门

目标：先在论文阅读中使用提示词，再理解如何把环境信息变成生成模型的文本条件。预计约 30–45 分钟可完成第一次练习。

## 1. 先记住一个结构（5 分钟）

**任务 + 背景/输入 + 约束 + 输出要求**

例如：
> 请根据下面的方法段落，整理模型输入、处理步骤、输出及损失函数。只依据提供的文字；没有说明的写“未说明”。用表格回答，并标注支持每项结论的原文位置。

相比“讲讲这篇论文”，这段话明确了要做什么、参考什么、缺信息时怎么办，以及如何输出。模型仍可能理解或引用错误，需回到原文核对。

## 2. 在研究中直接练习（10 分钟）

### 模板 A：拆解论文方法

> 我正在学习可见光到热红外生成。请根据我提供的论文方法部分，按训练和预测顺序整理：输入、各模块作用、损失和输出。对每一项注明原文章节或公式编号；无法从原文确定的写“未说明”。最后列出三个值得核实的问题。

### 模板 B：检查自己理解

> 以下是论文原文和我的理解。请逐条判断我的理解有原文支持、与原文矛盾，还是原文未明确说明。每条给出对应依据；不要把通用做法当成论文实现。

将实际论文段落和自己的理解接在提示后；没有提供原文时，模型可能无法准确核对。

## 3. 代码里怎样批量使用（10 分钟）

提示模板用字符串保存，输入数据逐条填进去。以下只演示生成字符串，不会调用模型：

```python
def make_prompt(paper_text: str) -> str:
    return f"""根据下面的论文片段整理输入、方法和输出。
只使用片段中明确给出的信息；缺失内容写“未说明”。
输出三列：项目、解释、原文依据。

论文片段：
{paper_text}
"""

texts = ["论文片段一……", "论文片段二……"]
prompts = [make_prompt(text) for text in texts]
print(prompts[0])
```

随后用实际模型提供商的 SDK，将每条字符串提交给模型，并保存输入、模型版本和输出。**把示例写进 prompt 属于上下文输入；这一步本身不会更新模型参数。**

## 4. 用于图像生成研究时要分清两种用途（10 分钟）

- **让大语言模型帮助分析论文**：提示里写任务、原文、约束和输出格式；评价回答是否忠于原文。
- **给图像生成模型提供环境文本条件**：把温度、湿度等数据写成与训练一致的文本模板，经模型对应的文本编码器传入；评价生成图是否符合目标及条件。

环境文本示例（教学模板，并非 AV2T-Gen 原始模板）：

```python
def env_prompt(temperature_c: float, humidity_pct: float) -> str:
    return (f"Air temperature: {temperature_c:.1f} degrees Celsius. "
            f"Relative humidity: {humidity_pct:.0f} percent.")

print(env_prompt(28.0, 50.0))
```

AV2T-Gen 风格方法通常还需要 RGB 图、对象状态与空间条件；环境文本只是其中一部分。这个模板不会自动赋予模型物理规律，也不能保证数值被准确理解。已有模型优先遵循其训练时的模板与编码方式，替换模板可能导致分布变化。

## 5. 做一个可检查的小实验

1. 先明确目标：例如，在有配对热图的测试样本上，比较提供环境文本是否有用。
2. 固定数据划分、模型、采样设置和随机种子；记录提示模板与单位。
3. 比较原训练条件与合法的无环境条件或受控替换条件。若模型没有针对缺失条件训练，删除提示可能造成分布外输入，结果须谨慎解释。
4. 使用配对图像指标及车辆区域评估，查看每个场景的结果；多个随机种子可帮助判断波动。
5. 不要只凭生成图好看就推断绝对温度准确；物理准确性需要经过校准的热数据和对应测量。

若要比较两种模板，明确是使用同一个已训练模型推理时改写，还是分别训练：前者可能存在训练/推理模板不匹配，后者需要控制训练预算。一次实验只能支持其设置范围内的结论。
